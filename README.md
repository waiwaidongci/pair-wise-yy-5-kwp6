# 手工织锦纹样排版台

直接打开 `index.html` 使用。支持网格绘制、色线统计、撤销重做、**打样版本管理**和导出 JSON。

## 版本化工作区

原来只有一份随时会变的本地稿，恢复旧配色会盖掉新稿。现在分三层：

| 文件 | 职责 |
| --- | --- |
| `archive.js` | 存档：localStorage 读写、数据规整与深冻结、旧版单稿（`zfl31Pattern`）自动迁移 |
| `state.js` | 状态管理：工作稿编辑、提交冻结、从旧版派生、重名/空名拒绝、用量快照 |
| `app.js` | 界面交互：渲染网格/色板/统计/版本历史，绑定全部事件 |

使用规则：

- **工作稿**：当前正在画的网格与备注，改动自动暂存在本机，随时可改。
- **提交打样**：填写版本名称后提交，当前**网格、色线用量、备注**被深拷贝并冻结，
  成为版本历史中的新一版；之后继续编辑工作稿不会影响任何已提交版本。
- **重名拒绝**：版本名称不能为空，也不能与已有版本重名——重名时会明确提示原因，
  因为同名会导致恢复旧配色时分不清是哪一稿。
- **从旧版开始**：在版本历史里点「从此版开始编辑」，会以该版为起点生成新的工作稿
  （会标记"自第几版续作"），旧版本原封不动；编辑后再提交即成为下一版。
- **版本顺序**：提交先后固定为第 1、2、3… 版，历史面板默认倒序展示，
  每版都保留独立的用量快照、网格缩略图与备注。
- **导出**：导出包含全部版本（含用量快照、续作关系）和当前工作稿的完整 JSON。

存档键为 `zfl31BrocadeArchive.v1`；首次打开时若检测到旧键 `zfl31Pattern`，
会自动把旧稿迁成工作稿（不丢稿）。

## 验证

`archive.js` 与 `state.js` 不依赖 DOM，可用 Node 直接验证冻结、派生、重名拒绝、
用量快照与持久化往返逻辑。
